# Ozmosis v0.80.14.16

## Export Save / Import Save File Workflow

Ozmosis v0.80.14.16 is a narrow save-management UX patch after v0.80.14.15.

It makes save handling explicit in the existing Settings/Data area:

- `Export Save` downloads a local `.json` save file.
- `Import Save` opens the existing file picker for a local `.json` save file.
- Imports validate the selected payload before writing to localStorage.
- Failed imports keep the existing browser save untouched.
- Derived progress-summary data remains rebuildable and is not required in older valid saves.

## What Changed

- Re-labelled the primary save buttons as `Export Save` and `Import Save`.
- Added a short save-workflow status line near the buttons.
- Added `buildOzmosisSavePayload()` for the current export payload.
- Added `validateOzmosisSavePayload(...)` for in-memory validation before import.
- Added a transaction-style import apply path that snapshots relevant localStorage keys before writing.
- Changed exported save filenames to the `ozmosis-save-v0_80_14_16-YYYYMMDDHHMM.json` pattern.
- Updated app/export metadata to:
  - `v0.80.14.16 - Export Save / Import Save File Workflow`
  - `v0.80.14.16-save-file-workflow`

- `ozmosis_b1_sprint_progress_v1`
- `ozmosis_b1_progress_evidence_v1`

The progress-summary cache is rebuilt after import and is not trusted over raw evidence.
