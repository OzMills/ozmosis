## 4. Current Repair Flow Before Patch

v0.53.1 already avoided the worst nonsense pseudo-diff for very short unrelated answers, but repair metadata was not exposed consistently and feedback depended mostly on token diff plus raw item `microRule`.

## 5. Repair Metadata / Category Handling

Added derived `b1RepairCategory(...)` handling for repair evidence and debug item metadata. New repair evidence records can now carry additive `errorCategory` values such as `article`, `case`, `number_agreement`, `word_choice`, `word_order_subordinate`, `word_order_main_clause`, or conservative `repair`.

## 6. Repair Feedback Implementation

Repair feedback now keeps the corrected form visible, shows the learner answer when useful, uses safe fallback copy for nonsense/unrelated answers, and only shows token-level change text when no clearer rule hint is available.

## 7. Capitalisation Handling

Validated with `b1_vocab_untersuchung_004`: `Die untersuchung dauert lange.` shows `Untersuchung is a noun and needs a capital letter.`

## 8. Word-Order Repair Handling

Validated with connector repair items such as `damit` / `sodass`: wrong verb form/order feedback shows the concise subordinate-clause rule, `In a subordinate clause, the conjugated verb goes to the end.`

## 9. Long Answer Submission Handling

Validated a long multi-word wrong repair answer. It submitted, recorded one evidence item, and used the safe fallback without clipping or route breakage.
