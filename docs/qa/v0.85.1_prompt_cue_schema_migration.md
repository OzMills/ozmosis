## 6. Schema Problem Summary

Imported source rows mixed task instruction, learner stimulus, cue, hint/support, post-answer explanation, and source/audit metadata. The visible runtime could therefore expose labels such as `show vs find`, `Kurs vs Unterricht`, family labels, or backtick-delimited planning text.

## 7. New Display/Cue/Hint Model

Added a display model with these conceptual fields:

- instruction
- stimulus
- cue text and cue role
- cue visibility
- hint text and hint visibility
- support text and support visibility
- internal label
- contrast note
- display status
- review queue reason

## 8. Renderer Changes

`b1PromptHtml(...)`, support rendering, production-card rendering, normal-practice eligibility, and debug output now use the display model. Sanitised-empty prompts stay empty instead of falling back to raw source text.

## 9. Cue Visibility Rules

Meaning-choice and generic-choice items that require meaning support now show a cue before answer. Under-contextualised typed clozes receive a visible context cue where a safe resolver can derive one; unresolved cases are queued for review.

## 10. Hint Button Behaviour

The existing hint button is now routed through the B1 display model when a B1 item has explicit hint text. No broad hint-content generation was added. The final audit found `0` explicit hint-reveal items in the current resolved set.

## 11. Data Cleanup Method

The content banks were not broadly rewritten. Runtime display cleanup is resolver-based. Unresolved source rows are queued in CSV for later controlled source cleanup.

## 12. High-Confidence Auto-Fixes

- Backtick/internal contrast prompt labels hidden from learner-facing prompts.
- `show vs find` style labels replaced by neutral instructions plus visible cues.
- `B1-Niveau` cloze context shown as `Sie nennen Ihr Sprachniveau.`
- Production-card source prompts reduced to clean German task instructions.
