# Ozmosis v0.85.9 Metadata Manifest Schema

## 1. Manifest File Location

`content/b1-metadata-manifest.js`

## 2. Manifest Global Name

`window.OZMOSIS_B1_METADATA_MANIFEST_V1`

Helper globals are also exposed for QA/debug use: `window.b1MetadataManifestLookup`, `window.ozmosisB1MetadataManifestLookup`, `window.b1GetCanonicalItemMetadata`, and `window.b1MergeItemMetadataWithManifest`.

## 3. Manifest Version

`b1-metadata-manifest-v1`, generated for `v0.85.9`.

## 4. Allowed Fields

The manifest stores metadata only: item ID, source file, bank/route/module/category/path ownership, task/answer/support/evidence metadata, review and production status markers, source row identifiers, cleanup markers, v0.2 apply-gate status, provenance, and confidence. It does not store prompts, stimuli, answers, accepted answers, choices, model answers, or feedback text.

## 5. Forbidden Fields

Learner-facing German/English content, answer keys, accepted answers, choices, scoring values, evidence records, progress records, generated examples, and new semantic claims are forbidden.

## 6. Explicit vs Deterministic vs Derived Provenance

- `explicit`: enough metadata already exists on the source item.
- `deterministic_default`: stable defaults came from the accepted display-schema bank defaults or source file ownership.
- `derived_fallback`: used only when a safe deterministic fallback is needed and documented.
- `missing`: unsafe semantic fields are omitted instead of guessed.

## 7. Duplicate Item IDs

Duplicate item IDs block unique manifest entries. v0.85.9 found 0 duplicate IDs.

## 8. Missing Metadata

Missing target-family, review-group, and target-ID fields are not inferred. The manifest may still include safe source/bank/route/status metadata while the missing semantic fields are recorded in the deferred-row CSV.

## 9. Runtime Readers

The manifest may be read by Dev Tools, QA, review-preparation tools, and metadata coverage checks. It must not change route availability, recommendation decisions, scoring, evidence, task-depth, production evidence, or review scheduling in v0.85.9.

## 10. Learner-Facing Behaviour

Learner-facing behaviour must remain unchanged. Explicit item metadata wins over manifest metadata, manifest metadata fills only stable known fields, and existing derived fallback remains available for missing or ambiguous values.
