## 4. v0.85.5a Proof Problem Confirmed

Confirmed. The v0.85.5a contact sheet and screenshot folder were inspected, and the visible artefacts showed the first-run language gate rather than the staged Satzbau states.

## 5. Root Cause

The previous harness could stage and query target DOM while the first-run language gate remained visible above it. That made DOM assertions misleading and screenshot artefacts invalid.

## 6. First-Run Language Gate Handling

The repaired harness completes the gate through the real UI: it selects English, clicks Start, waits for the overlay to disappear, and then stages the proof states. No new persistent storage keys were added.

## 7. Screenshot Validity Assertions

Accepted. The harness now fails if first-run language-gate text is visible in a staged screenshot and requires every screenshot to show the target state named by the filename.

## 8. Satzbau Default State Proof

## 9. Tap-to-Build Proof

## 10. Clear/Reset Proof
