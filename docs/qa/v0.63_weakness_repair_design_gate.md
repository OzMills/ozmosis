## 4. Current Pattern/Error-Type State Before Patch

v0.62 exposed possible patterns and Recent error types, but did not decide whether any signal was safe enough to become a repair candidate.

## 5. Repair Candidate Model

Added derived repair-candidate helpers that produce candidate IDs, source pattern/error-type IDs, family, skill node, task depths, evidence counts, similar-error counts, metadata quality, route fit, missing metadata, and conservative learner copy.

## 6. Readiness Thresholds

Readiness uses `not_ready`, `watch`, `candidate`, and `routeable`. One wrong answer cannot become routeable. Repeated evidence, at least two similar errors, enough matching items, non-diagnostic evidence, non-production-only evidence, and an existing route are required before routeable status.

## 7. Route Fit Handling

Route fit uses existing routes only: Grammar repair, Connector Sprint, Case Trainer, Redemittel, Wortschatz, Learning Map, or closest-route wording. No new route was created.

## 8. Insufficient Evidence Handling

No evidence produces no candidate. Thin evidence remains watch/not ready and cannot produce a routeable candidate.

## 9. Diagnostic Evidence Handling

Diagnostic-only evidence does not produce a routeable repair candidate.

## 10. Self-Marked Production Handling

Self-marked production-only evidence does not produce a routeable repair candidate and is treated as a limitation.

## 11. Support / Confidence Handling

Support/confidence signals remain context only and are not routeable repair families.

## 12. Learning Map Impact

Learning Map now shows a compact `Repair candidates` section when repeated evidence supports it. Details are behind native `details/summary`.

## 13. Recent Error Types Impact

Recent Error Types remain intact and feed repair-candidate readiness without being replaced.
