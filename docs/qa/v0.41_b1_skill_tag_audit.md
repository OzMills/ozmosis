## 9. Confidence Evidence Relevance

v0.40.1 confidence values are useful calibration evidence:

- correct + `sure` can support stronger future review confidence;
- correct + `unsure` can flag fragile knowledge;
- correct + `guessed` can flag low-quality success evidence;
- wrong + `sure` can flag possible misconception, but not enough to diagnose one;
- wrong + `unsure` or `guessed` supports low-confidence failure evidence.

Confidence must not be treated as mastery. It is most useful when combined with taskDepth, bank key, skill cluster, repeated evidence, and delayed review. Production-card confidence is weaker than auto-graded confidence because production cards are self-marked.

## 14. Transfer Testing / Interleaving Readiness

Transfer testing is partly ready at bank and type level, not target level.

Current metadata supports simple interleaving by bank/task type. It does not yet support robust target-based interleaving such as:

- connector meaning followed by word-order repair;
- Redemittel recognition followed by production transfer;
- Wortschatz cloze followed by error repair;
- case/article form followed by sentence transfer.

Needed fields: `contrastTargets`, `transferTarget`, `reviewGroup`, `targetId`, `variantId`, `taskDepth`, and explicit skill nodes.

## 19. Risks if Learning Map is Built Now

Risks:

- Learner may see precise progress claims based on fallback tags rather than explicit skill nodes.
- Correct recognition choices may be overvalued against harder cloze/repair/production tasks.
- Production-card self-marked evidence may be mixed with auto-graded evidence.
- Confidence may be mistaken for mastery.
- Weakness repair may prescribe the wrong target if target IDs are absent.
- Repeated surface prompts may inflate apparent progress without variant-family metadata.

Mitigation for v0.42: build a data scaffold that records evidence strength, metadata source (`explicit` vs `derived`), and "not enough evidence" states. Do not expose polished mastery labels yet.
