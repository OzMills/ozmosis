## 4. Current Error Pattern Logic Before Patch

v0.60 had cautious repeated-error pattern signals for connector word order, connector confusion, case/article, repair, and support/confidence context. It already required repeated evidence, but learner cards still exposed counts by default and debug output did not yet include a repair-readiness map.

## 5. Pattern Signal QA

v0.61 added signal-quality metadata, limitations, diagnostic/self-marked suppression, and a debug audit summary. Signals remain derived at read/render time.

## 6. Threshold Handling

Learner-facing patterns still require at least three relevant attempts and at least two similar errors. One wrong answer and two thin attempts remain suppressed.

## 7. Thin Evidence Handling

Thin evidence returns no learner-facing signal. The gate verified one wrong answer and two relevant wrong attempts do not create a possible pattern.

## 8. Diagnostic Evidence Handling

Diagnostic-only evidence is suppressed for learner-facing possible-pattern signals. Mixed diagnostic evidence receives a limitation label.

## 9. Support / Scaffolded Evidence Handling

Support-heavy and scaffolded-majority signals are marked with limitations. The support/confidence context signal remains a context signal, not a score or diagnosis.

## 10. Production Evidence Handling

Self-marked production-only evidence cannot create correctness or error-pattern claims.

## 11. Learner-Facing Copy Audit

The Learning Map possible-pattern UI remains cautious:

- `Possible pattern`
- `Repeated signals only`
- `not a diagnosis`

No active learner-facing diagnosis, mastery, pass/fail, or weakness state was introduced.

## 12. Recommendation Impact

Suggested Next Practice remains conservative. v0.61 did not replace the recommendation engine or add weakness repair routing.

## 13. Learning Map Impact

Possible-pattern cards are more compact. Counts, family, and limitations now sit behind a native details reveal.

## 14. Skill Matrix Consistency
