## 4. Evidence Schema Implemented

Evidence is stored as:

```json
{
  "schemaVersion": 1,
  "records": []
}
```

Each evidence record is appended through `appendB1EvidenceRecord()` and capped through `safeSetB1Evidence()`.

## 7. Fallback Metadata Rules

`bankKey` is resolved by looking up the item ID in `B1_CONTENT_REGISTRY`.

`skillTags` prefer existing `skillTags` and `tags`, then add conservative bank/task fallbacks such as:

- `connectors`
- `redemittel`
- `wortschatz`
- `b1_core`
- `word_order`
- `repair`
- `production`

`grammarFocus` prefers existing item fields such as `grammarFocus`, `targetRule`, `family`, `variantFamilyId`, `grammarDomain`, `courseDomain`, `section`, `topic`, `subtopic`, and `microRule`, then falls back to the bank key.

## 9. Confidence / Calibration Handling

Result: PASS.

No confidence UI was added. Evidence records include `confidence:null`. The app does not infer confidence from speed, correctness, or engagement.

## 10. AttemptContext Handling

Attempt context is conservative:

- `production` for production-card mark-practised records.
- `retry` for known extra-practice/daily retry contexts.
- `first_try` only when no prior evidence or B1 progress exists for the item.
- `unknown` when the app cannot safely distinguish review/retry/first exposure.

## 11. TargetId / VariantId Handling

Result: PASS.

Evidence records copy existing `targetId` and `variantId` fields only if present. The patch does not mutate item banks and does not infer new variant families.

## 12. SurfacePromptHash Handling

Result: PASS.

`surfacePromptHash` is generated by a tiny deterministic local hash helper over the visible prompt surface. It is not cryptographic and is intended only for future local prompt-repetition checks.

## 13. ErrorCategory / NearMissType Handling
