## 8. Export Save Behaviour

`Export Save`:

- builds the current Ozmosis save payload;
- includes existing export fields and additive metadata;
- serialises pretty JSON;
- uses a Blob/object URL;
- downloads with filename pattern `ozmosis-save-v0_80_14_16-YYYYMMDDHHMM.json`;
- does not modify learner progress;
- does not send data anywhere.

## 9. Import Save Behaviour

`Import Save`:

- uses the existing hidden file input;
- accepts `.json` / `application/json`;
- reads with `FileReader`;
- parses JSON;
- validates in memory;
- applies only after validation passes;
- clears/rebuilds derived summary after successful import;
- refreshes the app state after successful import.

Native file-picker cancel behaviour was not manually browser-tested. The code reports `Failed due to no file selected.` when the change handler receives no file; browsers that do not fire `change` on cancel remain silent.

## 10. Validation / Safety Summary

`validateOzmosisSavePayload(...)` checks:

- payload is an object;
- payload has Ozmosis metadata or known save fields;
- app/version metadata is structurally compatible when present;
- required save data exists;
- sprint progress shape is safe;
- evidence shape is safe;
- unlock override shape is safe;
- review queue shape is safe;
- derived summary is optional and not trusted.

`applyValidatedOzmosisSave(...)`:

- validates before mutation;
- snapshots relevant localStorage keys;
- writes only validated/normalised fields;
- rebuilds derived summary from raw evidence;
- restores the snapshot if apply throws.
