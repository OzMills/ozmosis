## 4. User-Reported Issues

Manual testing reported non-working Satzbau chunk taps, iOS/Safari zoom risk on text-entry fields, and Satzbau chunks displayed in answer-giving order.

## 5. Satzbau Interaction Before Patch

Satzbau chunks were visual chips. They did not provide the expected tap-to-build interaction.

## 6. Satzbau Interaction Implementation

Satzbau chunks now render as buttons with stable token IDs. Tapping a chunk appends it to the answer in tap order. Selected chunks show selected state, and Clear resets selected chunks and the typed answer.

## 7. Satzbau Randomisation Implementation

Chunk order is shuffled per attempt from the item/attempt seed and remains stable during focus, typing, checking, and feedback. If a shuffle matches the correct order, the display order is rotated when possible.

## 8. Satzbau Manual Typing Preservation

Manual typing remains available in the same answer field. If typed text diverges from selected chunks, typed input remains the source of truth.

## 9. Satzbau Answer Checking Preservation

Checking still uses the existing B1 answer path. The harness verified a manually typed correct Satzbau answer reaches success feedback.

## 10. iOS/Safari Input Zoom Risk

The risk was text-entry controls computing below 16px on mobile/touch layouts.

## 11. Input Font-Size Repair

Mobile/touch CSS now gives input, textarea, select, editable, B1 inline cloze/Satzbau, correction textarea, and Case Trainer text-entry controls a 16px minimum computed font size.

## 12. Visual State Results

Screenshots verify default randomised chunks, one-token selection, multiple-token selection, Clear/reset, manual typing, fail feedback, success feedback, and non-regression states.

## 13. Responsive and Keyboard Results

Edge/CDP checked 430x932, 390x844, 320x568, 430x520, 320x360, and 1365x599. No body overflow was detected in the Satzbau checks. Chunks are focusable button controls.

## 14. Choice/Cloze/Correction Non-Regression

Choice, cloze, and correction screenshots were regenerated. The harness verified cloze and correction input font sizes at 16px or larger.

## 15. Article Grid Preservation

The article-grid adapter remained present during the cases/articles repair check.

## 16. Export/Import Results

The harness built an export payload, validated it, applied it through the current import path, and rejected a malformed save.

## 19. Tests Not Run and Why

Manual physical iPhone/Safari testing was not run in this environment. The harness verifies the computed font-size condition that causes iOS/Safari input zoom risk.

## 20. Known Risks

Satzbau randomisation depends on current item tokenisation. One-token or otherwise unshuffleable items cannot produce a visibly different order and are documented as unshuffleable by the harness logic.
