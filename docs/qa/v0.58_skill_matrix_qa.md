## 4. Current Skill Matrix Logic Before Patch

Before v0.58, cells were mainly promoted from raw `evidenceCount`, positive counts, incorrect counts, and confidence counts. Limitations existed for production, diagnostic, derived metadata, support exposure, and delayed review, but the cell state did not consistently cap thin, scaffolded, diagnostic-only, self-marked-only, derived-only, or unknown/legacy task-depth evidence.

## 5. Evidence Inflation Risks Found

Risks found: one or two attempts could look stronger than warranted, scaffolded evidence could count like unassisted evidence, diagnostic-only records could look stable, self-marked production could look like task ability, derived metadata was not strong enough as a QA cap, and unknown task depths were not explicitly identified as legacy/unknown risk.

## 6. Sample Size Handling

Added `sampleSize`, `thinSample`, `usableEvidence`, and `canSupportProgress` metadata. One-record and two-record cells remain Not enough evidence unless enough non-diagnostic/non-production usable evidence exists.

## 7. Task-Depth Separation

Existing task-depth columns were preserved. The patch adds QA metadata to each cell without merging recognition, cloze, repair, contrast, production, diagnostic, review, or unknown task depths into one ability claim.

## 8. Support-Level Handling

Added support mix summaries with unassisted, scaffolded, unknown, scaffolded-majority, and no-unassisted flags. Scaffolded-majority and no-unassisted evidence cap learner-facing state advancement.

## 9. Production Evidence Handling

Self-marked production now carries `self_marked_only` inflation risk where applicable. Production cells show self-marked practice limitations and cannot imply automatic correctness from self-marking alone.

## 10. Diagnostic Evidence Handling

Diagnostic-only cells carry `diagnostic_only` inflation risk and remain evidence-limited. Diagnostic evidence remains a snapshot, not stable ability or placement.

## 11. Derived Metadata Handling

Derived-only cells carry `derived_only` inflation risk. Derived metadata is shown as a compact limitation badge and does not produce overconfident learner-facing state escalation.

## 12. Empty Cell Handling

Empty cells remain neutral as Not tested. Empty cells are not counted as failures and keep the existing learner-facing limitation copy.

## 13. Unknown / Legacy Task Depth Handling

Unknown task-depth cells now carry `unknown_or_legacy_task_depth` only when evidence exists in that unknown/legacy cell. Empty unknown cells are not flagged.

## 14. Mobile Matrix Presentation Handling

The v0.57.2 mobile card presentation was preserved. Cards now include compact limitation labels for thin sample, scaffolded, diagnostic snapshot, self-marked, derived metadata, and legacy metadata where present.

## 15. Learner-Facing Copy Audit

Active learner-facing states remain limited to Not tested, Not enough evidence, Introduced, Emerging, and Developing. No learner-facing Mastered, Reliable, Durable, Transfer-ready, B1-ready, Failed, Misconception likely, Slipping, Over-practised, overdue review state, rank, percent mastery, or weak-signal recommendation copy was added.

## 16. Debug / Dev Tools Impact

`debugSkillMatrixSummary()` now exposes QA counts for thin samples, scaffolded cells, diagnostic-only cells, self-marked-only cells, derived-only cells, legacy task-depth cells, and inflation-risk counts. Existing debug snapshot access remains unchanged.
