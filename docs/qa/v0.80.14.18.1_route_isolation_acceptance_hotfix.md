The previous v0.80.14.18 QA result is therefore superseded for route isolation.

## 3. Root Cause

The route functions set `homeScreen.hidden = true`, but a later landing CSS rule forced Home visible:

`body.homeMode .homeScreen { display:flex !important; }`

That rule could override the earlier `.homeScreen[hidden] { display:none !important; }` rule while `body.homeMode` was active.

## 4. Implementation Summary

- Added a late high-specificity CSS hidden guard for top-level route screens.
- Added `setActiveScreen(...)`, `setRouteScreenHidden(...)`, `currentActiveScreenId(...)`, and `routeScreenForState(...)`.
- Updated Home, Learning Map, Settings, hub, setup, and practice-start paths to use the active-screen helper.
- Updated Dev Tools overlay handling so persistent route screens are hidden while Dev Tools is open and restored when it closes.
- Updated version metadata to v0.80.14.18.1.
