## 6. Learning Map Data Shape

The scaffold is exposed through:

```js
window.ozmosisB1Debug().learningMap
```

The returned object has this shape:

```js
{
  schemaVersion: 1,
  generatedAt: "ISO timestamp",
  levelTrack: "B1",
  nodes: [...],
  currentFocus: null,
  recommendedNextSeed: null,
  malformedEvidenceCount: 0,
  unmappedEvidenceCount: 0,
  limitations: [...]
}
```

Each node includes:

- `key`
- `label`
- `cluster`
- `state`
- `evidenceCount`
- `correctCount`
- `incorrectCount`
- `confidenceCounts`
- `taskDepthCounts`
- `bankCounts`
- `metadataProvenance`
- `lastPractisedAt`
- `hasEnoughEvidence`
- `limitations`

The scaffold is derived from existing evidence. It does not create a new persistent Learning Map storage key.

## 8. Evidence Aggregation Rules

Evidence-to-node assignment uses conservative matching:

1. Prefer explicit item-level `skillTags` if present.
2. Use existing derived evidence fields such as `skillTags`, `grammarFocus`, `bankKey`, `taskType`, and `taskDepth`.
3. Use bank-specific matching for `connectors`, `redemittel`, and `wortschatz`.
4. Use task-depth matching for `repair`, `production`, and `word_order`.
5. Count unknown or unmapped evidence without throwing.

The bank-level nodes were intentionally narrowed so a Wortschatz item with a broad topic such as `applications` does not automatically count as Redemittel unless future explicit metadata says it should.

## 9. Metadata Provenance Rules

Metadata provenance is tracked per node contribution:

- `explicit`: item-level canonical `skillTags` matched the node.
- `derived`: evidence was matched from bank, task type, task depth, tags, topic, grammar focus, or fallback metadata.
- `unknown`: evidence could not be safely classified.

Current v0.42 evidence is expected to be mostly `derived` because v0.41 found no canonical explicit skill-tag coverage.

## 10. Progress State Rules

Allowed v0.42 states:

- `not_enough_evidence`
- `introduced`
- `emerging`
- `developing`

Rules implemented:

- `not_enough_evidence`: zero relevant evidence records.
- `introduced`: one or two relevant evidence records.
- `developing`: at least three correct records across at least two non-unknown task depths.
- `emerging`: fallback state for evidence above introductory level that does not meet `developing`.

The scaffold does not emit `reliable`, `durable`, `transfer_ready`, or `mastered`.

## 11. Confidence Handling

The scaffold counts existing v0.40.1 confidence values:

- `sure`
- `unsure`
- `guessed`
- `unset`

Confidence is treated as calibration evidence only. It is not treated as correctness or mastery.

## 21. Known Limitations

- Metadata remains mostly derived, not explicit.
- The scaffold is intentionally coarse and should not drive polished learner-facing claims yet.
- There is no Learning Map UI.
- There is no Skill Matrix UI.
- There is no diagnostic sprint.
- There is no weakness repair.
- There is no Leitner or durability scheduling.
- There are no transfer-ready or mastery states.
- Node assignment is conservative but still depends on fallback evidence quality until item-level metadata is repaired.
- `currentFocus` and `recommendedNextSeed` are `null` in v0.42 to avoid speculative recommendations.
