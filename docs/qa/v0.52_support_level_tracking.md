## 6. New Evidence Record Impact

New evidence records now include additive fields:

- `supportLevelSchemaVersion`
- `supportLevel`

Observed Edge/CDP records:

- Typed unassisted item: `supportLevel = "unassisted_typed"`
- Choice unassisted item: `supportLevel = "unassisted_choice"`
- Teach me assisted item: `supportLevel = "teach_me_assisted"`
- Production Mark practised item: `supportLevel = "self_marked_production"`

## 7. Legacy Evidence Handling

Older evidence without `supportLevel` remains readable.

Edge/CDP injected a legacy evidence record with no support-level field; debug/evidence summary read it safely and derived `unassisted_typed` from answer mode plus support flags.

## 8. Learning Map Impact

Learning Map still renders and remains conservative. The matrix detail copy now states that support level is evidence context, not score.

## 9. Skill Matrix Impact

Skill Matrix data now carries support-level counts additively. Matrix cells can include the limitation:

`Includes scaffolded/self-marked evidence; support level is evidence context, not score.`

No learner-facing state labels were broadened.

## 10. Recommendation Impact

No recommendation scoring or route selection was changed.

## 11. Diagnostic Impact

Diagnostic attempt context remains diagnostic. Support level is additive context only and does not make diagnostic evidence an exam, placement, pass, or fail result.

## 12. Production Card Impact

## 25. Known Risks

- Support-level detection is intentionally conservative and limited to support exposure the current app can detect.
- Translation/support visibility before answer is still governed by existing support rendering; v0.52.1 is expected to add item-level visibility policy.
- The responsive verifier is headless Edge, not a real touch device.
